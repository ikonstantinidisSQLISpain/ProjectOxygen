# Project Oxygen

This is a Proof Of Concept Project, whose aim is to bring a series of SQLi PowerBI dashboards to a databricks instance managed by SQLi.

## Process

The pipeline to update the oxygen data consiste of 1 job of 3 steps, the first task is required to be executed before the pipeline and it gets the last snapshot date from file names.

Second is the pipeline it self that reads all the data and generates all the tables.

Third task adds all the table comments and column definitions.

## Setup

1. Create a volume where you will store all the metadata required for the pipeline to work. The volume needs the next:
    * Folder configurations: Used to store some of the steps that are applied to each table. It is devided into:
        * default.json: A file that stores the default configurations for the cases when some of the required fields are None.
        * tables_config.json: The specific configurations of each table.
    * Folder mappings: Some columns of the data only contain a code or ID, this folder stores the CSV files that map those codes into the value or name they represent.
        * bucu_department.csv: Maps practice name (department) to BU or CU.
        * collab_status_encoder.csv: Maps status code to status name from collab_status table.
        * department_zone.csv: Maps department name to department zone name (practice zone name)
        * site_maps.csv: Maps the site name to the country and zone.
        * zones.csv: Maps the zone id to zone name.
    * Folder schemas: This folder have all the files that have the top level json keys that wished to be parsed to a table column. It is a JSON of the shape, column_name: object, where object has one key indicating the type and a possible secondary key format if the type is date, indicating the date format.
    * Folder comments: Contains all the table and column comments. There should be a folder for each table containing two files:
        * metadata.yml: Contains all the data about the table.
        * schema.yml: Contains all the data about the columns.
        * The inner folder structure must be organized the next way:
            1. Quality: (Bronze, Silver, Gold)
            2. Platform: (Whoz, Analytic, ...)
            3. Table: (accreditation, profile, ...)
            4. Level: Indicating the category of the table. The possible values can be found in table names along with their meaning.
            5. YML file. metadata or schema
    * latest_snapshot.json: This is a file generated by the first task of the job. No need to modify it.
* pipeline and jobs yml file: This file contains all the pipeline parameters.
    * job_parameters:
        * latest_snapshots_file: The file containing the latest snapshot file generated by the first task.
        * comments_volume: The path to the volume with all the comments of the tables.
    * pipeline_parameters:
        * libraries: Right now there is a single files that has all the pipeline (see the current pipeline.yml file) that it is generated by the script `python_flattenizer_3.py`. Required to be run before pushing the code to databricks. (Serverless issue, it does not allow folder organization)
        * configuration:
            * catalog
            * raw.schema: Schema with raw files.
            * quarantine.schema: schema name for quarantine
            * quarantine.files: table name for quarantined files
            * qualities.bronze: name for bronze quality
            * qualities.silver: name for silver quality
            * qualities.gold: name for gold quality
            * bronze.raw: name for raw level of tables.
            * bronze.base: name for base level of tables.
            * bronze.current: name for current level of tables.
            * platforms.whoz: name for whoz platform.
            * platforms.analytic: name for analytic platform.
            * platforms.perso: name for perso platform.
            * platforms.cra: name for cra platform.
            * platforms.project: name for project platform.
            * history.filter_expression: Filter expression for history data.
            * volume.data: default volume path for all data.
            * volume.schema: default volume path for all schemas data.
            * volume.config: default volume path for all tables configs
            * file.schema: default file name with all schemas data about tables.
            * file.config: default file name with all configs about tables.
            * file.default_config: default file name with default config json. Required for missing configured raw data read.
            * volume.data.`platform`.`table`: Volume with all data about `platform` and `table`.
            * glob.data.`platform`.`table`: Glob regex that identifies the raw files for `platform` and `table`.
            * file.schema.`platform`.`table`: File with schema data about `platform` and `table`.
            * file.encode.`name`: File path to `name` mapping. Possible names:
                * collab_status
                * zone_map
                * department_bucu
                * site_maps
                * department_zone_map
            * file.latest_snapshot: File path with latest snapshot data.
